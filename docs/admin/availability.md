# 服务健康与熔断器

本文档说明 Obsidian Arc 管理后台「服务健康」面板的配置参数、断路器熔断条件、探针自愈机制与指标重置逻辑。

---

## 架构与核心指标

「服务健康」面板由策略配置区与模型状态列表两部分组成：
- **模型标识与服务商**：模型真实 ID、对外展示名称与其所属的服务商；
- **当前状态徽标**：`🟢 up`（正常）、`🟡 degraded`（降级）、`🔴 down`（熔断下线）、`⚪ unknown`（样本不足）；
- **窗口可用率**：在当前配置的采样窗口内的请求成功百分比；
- **样本总量**：窗口内收集到的有效请求轮数；
- **24 柱时间线迷你图**：显示过去 24 小时每小时的连通状态切片。

---

## 策略配置参数

| 配置项 | 对应设置键 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| **主动轻量探测** | `health.probe` | `true` | 是否启用后台低频探测。模型在窗口内无真实用户请求时，发送单个 Token 的请求探测连通性。 |
| **统计滑动窗口** | `health.window_minutes` | `30` | 可用率与熔断计算的采样时间窗口（分钟）。 |
| **连续失败熔断** | `health.disable_after` | `0` (关闭) | 硬故障断路器。当模型连续失败达到指定次数（如 3 次）时，系统自动将模型标记为 `AutoDisabled` 并从前台隐藏。设为 `0` 表示不启用连续失败熔断。 |
| **低成功率熔断** | `health.disable_below` | `0` (关闭) | 软故障断路器。采样窗口内的请求成功率跌破指定百分比（如 70%）时触发熔断。 |
| **服务降级警报线** | `health.warn_below` | `90` | 可用率低于此百分比时，状态标记为 `🟡 degraded` 并在界面提示。 |
| **普通用户端可见** | `health.show_users` | `false` | 是否允许未授权普通用户在前端访问 `/uptime` 看板（展示数据已脱敏）。 |
| **数据保留天数** | `health.retain_days` | `14` | 采样数据在数据库中的保留时长（天），超期数据由后台任务清理。 |

---

## 断路器与自愈恢复流程

### 做了什么
1. 当模型连续失败达到 `health.disable_after` 或成功率低于 `health.disable_below` 时，断路器自动将模型标记为禁用；
2. 禁用后，后台探针以设定的探测间隔持续发送最小化握手请求；
3. 当上游网络恢复且探针连续返回成功达到预设阈值时，系统自动清除禁用状态并将模型重新上线。

```text
       正常运行 (Up)
             │
             ▼ 连续失败 N 次 或 成功率 < M%
       触发熔断下线 (AutoDisabled)
             │
             ▼ 前台模型列表中自动隐藏
       后台探针低频探测上游
             │
             ▼ 上游恢复，探针连续成功
       自动重新上线 (Up)
```

### 为什么这么做
在上游服务商发生严重网络故障或机房宕机时，及时将不可用模型从前台隐藏，避免用户反复遭遇超时等待；上游恢复后自动恢复上线，减少运维人员手动排查与开机操作。

### 代价是什么
熔断阈值若设置过低（例如连续失败 1 次即熔断），在上游遭遇轻微网络抖动时会导致模型频繁下线并在探针成功后又重新上线，影响正在使用该模型的用户。

## 指标重置 (Reset Uptime)

### 做了什么
管理员在更换上游 Key、切换网络线路或完成服务商维护后，可点击「重置可用性统计」。系统在数据库中记录当前重置时间戳，此前产生的所有历史失败样本不再计入可用率分母，统计立即以新产生的请求为基准重新计算。

### 为什么这么做
历史长窗口（如 24 小时）内积累的失败记录会导致修复后的模型在数小时内仍显示为低可用率。通过显式重置可以快速刷新状态指示。

### 代价是什么
重置操作会清除历史样本参考价值，短时间内模型由于样本量较少，其状态徽章会临时显示为 `⚪ unknown`，直至积累到最低样本量。

## 运维约束与排查路径

### 失效场景
1. **上游服务商对探针 IP 封控**：部分严格风控的服务商可能会将周期性单 Token 探针识别为爬虫探测并返回 403，导致正常模型被探针误判为离线并触发熔断；
2. **上游欠费但返回 200 错误页面**：若上游服务在欠费时返回包含“余额不足”文本的 HTTP 200 响应，断路器将无法通过状态码识别该故障。

### 不明显的约束与前提
1. **主动探测触发前提**：主动探针仅在模型于设定滑动窗口内（如 30 分钟）完全没有真实用户请求时才触发；若模型持续有真实调用，系统完全复用真实请求的成功率指标，不额外产生探测开销；
2. **熔断配置生效边界**：`health.disable_after` 设为 `0` 表示彻底关闭连续失败熔断，而非失败 0 次熔断；
3. **指标重置范围限制**：重置可用性统计仅影响内存中用于展示状态的采样计算基准点，不会物理删除历史已写入数据库的请求日志流水。

### 排查步骤
1. **模型意外下线排查**：在管理后台「服务健康」中查看该模型的失败记录，并在「请求日志」中筛选该模型的错误详情；
2. **检查重置基准时间**：确认重置时间戳是否晚于上游故障发生时刻。
