# 后台概览与监控

本文档说明 Obsidian Arc 管理后台的权限边界、分包加载机制、子模块划分与系统状态采样。

---

## 权限边界与安全架构

### 1. 访问控制
- 访问路径为 `/admin`；
- 所有特权 API 统一收敛于 `/api/admin/*` 路径，由 `auth.RequireAdmin` 中间件进行身份核验。非管理员身份的请求直接返回 `403 Forbidden` 并写入安全审计日志。

### 2. 独立分包懒加载

#### 做了什么
管理后台所有前端代码统一打包进独立的 `AdminPage-[hash].js` 代码块。未访问 `/admin` 路径的普通用户在首屏加载时不会请求该文件。

#### 为什么这么做
将管理员专属的配置表单、图表与管理逻辑从主应用代码中剥离，减少普通用户进入聊天界面时的网络传输开销（节省约 36 kB 体积）。

#### 代价是什么
管理员首次点击进入管理后台时，需要通过网络额外异步拉取一次后台代码块，若网络延迟较高会感知到数百毫秒的面板加载过渡。

## 模块划分

管理后台划分为以下子模块：

| 模块 | 说明 |
| :--- | :--- |
| **仪表盘 (Dashboard)** | 汇总全站 24 小时活跃用户数、请求量、Token 吞吐量与错误率走势。 |
| **服务商管理 (Providers)** | 配置上游 API 服务商、基础 Base URL、API Key 与自定义请求头，执行连通性探测。 |
| **模型调度 (Models)** | 配置对外展示的模型、真实 Model ID、透明路由目标、推理风格与计费权重。 |
| **用户组 (Groups)** | 定义分组，配置模型白名单与组级配额限制策略。 |
| **用户管理 (Users)** | 检索用户、执行封禁解封、重置密码与个人额度微调。 |
| **兑换卡码 (Codes)** | 批量生成重置卡码、管理有效期与查看核销状态。 |
| **用量统计 (Usage)** | 统计各模型 Token 与点数消耗分布，支持导出详细账本 CSV 文件。 |
| **请求日志 (Logs)** | 实时记录所有调用流水，支持按状态码、耗时和模型检索并查看报错详情。 |
| **服务健康 (Availability)** | 查看模型实时在线率、24 柱可用性时间线直方图与重置采样指标。 |
| **全站公告 (Announcements)** | 发布对话区顶部横幅通知或全站弹窗公告。 |
| **安全风控 (Security)** | 配置 Turnstile 验证码、AI 注册审核规则与沙盒模拟测试。 |
| **系统资源 (Resources)** | 采样查看进程 CPU 占用率、内存占用、活动 Goroutine、连接池状态与数据库热备份下载。 |
| **系统设置 (Settings)** | 调整站点名称、首屏落地页形态、访客试用参数、SMTP 邮件等全局配置。 |

## 系统运行时采样

### 做了什么
后端包含轻量采样器，在管理员请求后台仪表盘或系统资源页面时，实时读取操作系统与 Go 运行时的指标：
- **CPU 使用率**：通过读取系统时间片差值计算当前进程的 CPU 负载；
- **常驻物理内存 (RSS)** 与虚拟内存；
- **Go 运行时指标**：当前活跃的 Goroutine 数量；
- **数据库连接池状态**：当前打开连接数、正在使用的连接数、空闲连接数与等待连接的请求数；
- **磁盘占用**：数据库文件体积与上传附件目录尺寸。

### 为什么这么做
使管理员无需登录宿主机终端即可直接在 Web 界面掌握进程的资源占用体征与连接池水位，及时发现并发瓶颈与内存增长。

### 代价是什么
每次采样需调用系统 API（在 Linux 下读取 `/proc` 文件系统，在 Windows 下调用性能接口），会带来微小的系统调用开销；采样仅在管理员主动打开或轮询该页面时执行。

## 运维约束与排查路径

### 失效场景
1. **连接池等待数持续增加**：若「系统资源」页面中数据库连接池的“等待数”大于 0，说明并发请求超过了 `OBSIDIAN_DB_MAX_CONNS` 设置，请求正在排队，需调大连接池或排查是否存在长耗时慢 SQL；
2. **Goroutine 数量单调递增**：若系统处于低流量时 Goroutine 数量持续攀升未回落，可能存在未正常退出的长连接协程或挂起的外部网络请求。

### 不明显的约束与前提
1. **动态分包隔离约束**：管理后台代码独立打包为 `AdminPage-[hash].js`，主入口代码严禁静态引用后台专有组件或工具，否则破坏 5-bundle 测试断言；
2. **即时采样无历史时序**：系统资源采样的 CPU、内存与 Goroutine 数据为当前时刻的实时切片，后端不维护长期的时序指标数据库，历史监控建议配合外部监控探针；
3. **Session 角色校验**：访问管理后台要求当前登录 Session 的 `role` 字段为 `admin`，修改角色的操作在下次会话刷新时生效。

### 排查步骤
1. **核对后台接口响应**：打开浏览器开发者工具 Network 面板，查看 `/api/admin/*` 的请求状态码与返回载荷；
2. **排查权限拦截**：若页面提示无权访问，核对当前登录账号在 `users` 表中的 `role` 是否为 `admin`。
