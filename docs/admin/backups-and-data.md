# 数据备份与迁移

本文档说明 Obsidian Arc 的数据存储目录结构、热备份机制、个人数据漫游与跨数据库引擎迁移步骤。

---

## 目录结构与备份要素

在 SQLite 模式下，系统状态保存在 `./data` 目录中：

```text
./data/
├── obsidian.db        # SQLite 数据库文件（包含用户、模型、对话、账本等数据）
├── secret.key         # 实例对称加密主密钥（用于解密上游服务商 API Key）
└── uploads/           # 用户上传的图片与文档附件物理存储目录
```

### 备份方法
打包备份整个 `./data` 目录：

```bash
tar -czvf obsidian-backup-$(date +%Y%m%d%H%M%S).tar.gz ./data
```

::: warning 密钥与数据库强绑定
`secret.key` 是解密数据库中上游 API Key 的凭据。若在迁移服务器时仅复制了 `obsidian.db` 而遗失了 `secret.key`，数据库内存储的所有上游 Key 将无法解密，调用模型时会抛出解密校验失败异常。
:::

## 管理后台热备份 (Hot Backup)

### 做了什么
管理员在管理后台「系统资源」中点击「下载数据库备份」按钮，后端在 SQLite 的 WAL 模式下创建一致性检查点快照，并将快照文件直接流式传输给浏览器下载。

### 为什么这么做
允许管理员在不停止运行中服务、不中断用户对话与 API 请求的前提下，获取可用的数据库备份。

### 代价是什么
在并发写入较高的场景下，生成检查点快照会占用额外的磁盘 I/O 资源，快照生成期间会轻微增加写入请求的排队延迟。

## 个人数据导出与导入 (`/api/backup`)

### 做了什么
用户可在个人中心将属于自己的历史会话、问答记录、附件引用和偏好设置导出为标准的 JSON 归档文件；在另一个 Obsidian Arc 实例中，用户可将该文件导入，恢复历史会话。

### 为什么这么做
支持个人用户在不同部署实例之间迁移个人对话资产，不依赖管理员介入。

### 代价是什么
大体量个人历史导出时，后端需要将用户的全部会话和消息加载进内存并序列化为 JSON，如果单用户历史长达数万条消息，会短时间占用较多内存。

## 跨引擎迁移 (SQLite ⇄ PostgreSQL)

### 做了什么
系统的数据库表结构与查询统一通过通用 SQL 子集编写。当需要从 SQLite 切换至 PostgreSQL 时，配置环境变量 `OBSIDIAN_DB_DRIVER=postgres` 与 `OBSIDIAN_DB_DSN` 启动服务，系统会自动在新数据库中创建全部数据表与索引。

### 为什么这么做
支持系统从单机轻量运行平滑过渡到支持多节点并发的集群架构，无需重写应用层代码。

### 代价是什么
数据表结构的自动迁移仅负责创建空表与索引，存量业务数据（历史对话、用户表、用量账本）的跨引擎迁移需要通过数据迁移工具（如 `pgloader` 或自定义脚本）进行数据格式转换和行导入。

## 运维约束与排查路径

### 失效场景
1. **热备文件不完整**：若在外部直接使用 `cp obsidian.db backup.db` 拷贝文件，而此时 WAL 文件（`obsidian.db-wal`）中尚有未合并的事务数据，会导致复制出的数据库文件处于损坏状态，必须通过后台热备接口或 SQLite 官方 `.backup` 命令进行备份；
2. **跨实例导入主键冲突**：若导入的 JSON 中包含与目标实例冲突的 ULID 主键，系统会重新生成主键或按规则处理，需核对消息的关联关系。

### 不明显的约束与前提
1. **密钥与数据文件强绑定**：`secret.key` 是对称解密上游服务商 API Key 的关键凭证。在迁移或备份时若仅备份数据库文件而丢失该密钥，已有服务商凭证将永久无法解密；
2. **迁移仅覆盖 DDL 结构**：切换至 PostgreSQL 时，程序启动仅自动执行数据表结构与索引的创建，存量历史消息与用户记录的跨引擎同步必须通过外部数据迁移工具处理；
3. **附件文件独立于数据库**：上传的图片与文档附件物理存储于 `./data/uploads/` 目录，单做数据库备份不包含图片二进制数据，完整灾备必须同步打包附件目录。

### 排查步骤
1. **验证备份可用性**：在离线环境下执行 `sqlite3 backup.db "PRAGMA integrity_check;"`，返回 `ok` 表示数据完整无损坏；
2. **密钥校验**：在新机器启动后，进入后台「服务商管理」对已有服务商点击「测试连接」，验证 API Key 能否正常解密调用。
