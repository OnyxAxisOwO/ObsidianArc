# 用户与分组管理

本文档说明 Obsidian Arc 管理后台中的用户账户生命周期管理、会话审阅审计、分组权限门禁与配额策略。

---

## 用户控制台 (Users Console)

管理员可通过后台「用户管理」模块对全站注册用户执行检索与状态干预。

### 1. 过滤与检索
- **全文检索**：支持按用户名、昵称或邮箱模糊查询；
- **维度筛选**：支持按用户组、角色（`admin` / `user`）以及账户状态（正常 / 封禁）进行组合过滤；
- **状态保持**：从用户详情面板返回列表时保留当前搜索与分页上下文。

### 2. 账号状态干预
- **封禁/解封**：封禁操作使该用户所有现有 Session 失效，并在认证中间件中拦截该账号发起的任何 API Key 调用；
- **重置密码**：管理员可直接为用户指定新密码，更新密码时将触发 Argon2id 重新哈希；
- **分组变更**：调整用户所属的用户组，即时更新其可用模型白名单与周期额度；
- **管理员数量原子保护**：当系统检测到全站仅剩最后一位活跃管理员时，行级锁保护机制会拦截任何降级或删除该管理员的操作，防止系统失去最高管理权限。

### 3. 会话审阅与审计记录

#### 做了什么
管理员可在后台审阅特定用户的历史对话记录（提问文本、模型回复与 Token 开销）。审阅操作位于显式的二级操作按钮后，且每次调阅均会在系统日志中记录一条包含管理员 ID、目标用户 ID 与时间戳的审计日志。

#### 为什么这么做
在排查安全违规、反作弊调查或企业合规审查时，需要核实特定会话内容；通过二级确认与留痕记录，防止运维人员无序越权查看用户对话隐私。

#### 代价是什么
管理员对对话的查看行为不可撤销地记录在日志中，增加了审计数据的存储开销；审阅面板一次性拉取长对话会产生较大的单次数据库查询负载。

## 用户组控制台 (Groups Console)

用户组用于统一管理模型授权、接口访问控制与配额策略。

### 1. 默认用户组约束
- 系统有且仅有一个用户组被标记为 `is_default`；
- 新注册用户默认归入该组；
- 默认组不能直接删除，必须先将其他组指定为默认组后方可删除原组。

### 2. 四大组级门禁开关

| 权限开关 | 对应字段 | 说明 |
| :--- | :--- | :--- |
| **全模型自动授权** | `allow_all_models` | 开启后，该组自动继承全站所有已启用模型的调用权限。新增模型无需逐组重新分配。 |
| **API 接口调用门禁** | `api_access` | 控制该组成员是否有权申请 API Key 并通过 `/v1` 调用网关。关闭后仅允许通过网页端交互。 |
| **耗时统计行可见性** | `allow_stats` | 控制前台收到回答后是否显示首字延迟（TTFT）、总耗时与 Token 生成速率。 |
| **会话删除合规防删** | `allow_delete_conversations` | 开启后允许用户自行删除对话；关闭后前端隐藏删除按钮，服务端拦截删除接口，满足合规审计留痕要求。 |

## 模型白名单与配额配置

- **模型白名单 (Model Grants)**：若未开启全模型自动授权，必须在模型列表中勾选允许该组访问的具体模型；
- **组级配额限制**：为用户组配置 5 小时、日、周、月的请求数、Token 数或点数上限，组内所有用户默认继承该规则（个人专属配置优先覆盖）。

## 运维约束与排查路径

### 失效场景
1. **用户被封禁后仍然在使用**：若封禁前建立的长连接请求正在流式生成中，该次已在传输中的 HTTP 连接不会被即时切断，直到该轮生成完毕或客户端断开后，后续请求才会被完全拦截；
2. **迁移用户组时配额重置问题**：当将用户从组 A 移至组 B 时，用户此前在组 A 时间窗口内已消耗的 Token 记录仍保留在账本中，系统在计算新组配额时会直接按当前窗口内已产生的累计消耗进行扣减，可能导致移入新组后立即触发额度超限。

### 不明显的约束与前提
1. **最后管理员锁定机制**：数据库事务通过行级锁排他统计管理员数量，最后一名有效管理员无法被降级、注销或删除，若需交接必须先晋升新管理员；
2. **默认组不可删除**：标记为 `is_default` 的用户组不可被删除，新注册用户自动绑定该组，若需清理必须先将其他组指定为默认组；
3. **防删开关仅限普通用户**：`allow_delete_conversations` 开关仅作用于非管理员身份，超级管理员始终具备删除会话的特权。

### 排查路径
1. **用户无法通过 API 调用**：在管理后台核对该用户所在用户组的 `api_access` 是否为开启状态，并核对 API Key 是否处于启用状态；
2. **防删开关未生效**：若配置了关闭删除但用户仍能删除会话，检查该用户所属分组是否正确，并核对前端是否有旧缓存未刷新。
