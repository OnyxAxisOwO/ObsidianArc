# 服务商与模型调度

本文档说明 Obsidian Arc 的服务商与模型解耦架构、密钥加密存储规则、透明路由映射与计费权重计算。

---

## 实体解耦架构

### 做了什么
系统将“服务商 (Provider)”与“模型 (Model)”设计为两个独立的数据库实体：
- **服务商**：定义连接协议（OpenAI 兼容或 Anthropic 规范）、Base URL、API Key 与自定义 HTTP Headers；
- **模型**：归属于特定服务商，定义真实上游 Model ID、对外展示名、API 外部别名、推理思维链风格、授权用户组与计费权重。

```text
┌─────────────────────────┐      ┌─────────────────────────┐
│  服务商 A: SiliconFlow   │      │   服务商 B: Anthropic    │
│  (Base URL, Key, Headers)│      │  (Base URL, Key, Headers)│
└────────────┬────────────┘      └────────────┬────────────┘
             │                                │
      ┌──────┴────────────────────────┐       │
      ▼                               ▼       ▼
┌──────────────┐              ┌──────────────┐
│ deepseek-chat│              │ claude-3-7   │
│ (模型元数据,  │              │ (模型元数据,  │
│  路由规则,   │              │  计费倍率,   │
│  授权用户组) │              │  授权用户组) │
└──────────────┘              └──────────────┘
```

### 为什么这么做
1. 单个聚合服务商（如 OpenRouter、SiliconFlow 等）往往同时提供数十款不同厂商的模型；
2. 允许管理员为来自不同渠道的同名模型配置独立的路由与故障隔离，无需在每个模型上重复配置服务商凭据与网络地址。

### 代价是什么
删改服务商时存在级联影响，若误删除了一个服务商，其下挂载的所有模型将被一并级联删除或失效；管理员配置新模型需要先创建服务商，操作步骤多于单一配置表单。

## 服务商管理 (Providers)

### 1. 协议类型
- **OpenAI 兼容规范 (`openai`)**：对接官方 OpenAI、DeepSeek、Groq、SiliconFlow 等兼容接口及本地部署的 Ollama / vLLM；
- **Anthropic 规范 (`anthropic`)**：对接官方 Anthropic Messages 协议，保留原生的 System Prompt 分离与 `thinking` 参数传递。

### 2. 凭证加密存储

#### 做了什么
服务商 API Key 存入数据库前，由后端使用由 `OBSIDIAN_SECRET_KEY` 派生的子密钥通过 AES-256-GCM 算法进行对称加密；管理后台在回显时将密钥替换为掩码字符串（如 `sk-••••••••`），前端接口不返回明文。

#### 为什么这么做
防止数据库备份文件外泄或数据库被低权限读取时直接导致上游 API 凭据泄露。

#### 代价是什么
每次调用上游模型前需要进行一次解密计算；若丢失了环境变量 `OBSIDIAN_SECRET_KEY`，数据库内存储的所有 Key 将永久无法恢复解密。

### 3. 自定义 Headers 与连通性测试
- **自定义 Headers**：支持针对第三方中转配置专属标头（如 OpenRouter 要求的 `HTTP-Referer`）；
- **模型自动探测**：点击「自动探测」调用上游 `/v1/models` 端点拉取模型列表，快速选择并添加。

## 模型调度与透明路由 (Models)

### 1. 标识体系
- **全局唯一标识 (ID)**：系统内部生成的 26 位 ULID 主键；
- **上游模型标识 (Model ID)**：提交给服务商 API 的真实模型名（如 `deepseek-ai/DeepSeek-V3`）；
- **展示名称 (Display Name)**：前台用户在下拉选择框中看到的名称；
- **API 外部别名 (`api_name`)**：供外部通过 `/v1` 接口调用时使用的模型名称（如 `gpt-4o`）。

### 2. 透明模型路由

#### 做了什么
管理员可为模型指定目标实际执行模型。例如将外部名称为 `gpt-4o` 的模型在后端路由重定向至 `deepseek-chat`。客户端在发起请求和接收响应时看到的模型名称保持为 `gpt-4o`，上游真实的路由目标对客户端透明。

#### 为什么这么做
允许管理员在不修改客户端配置、不影响终端用户使用的前提下，对底层模型进行无感平替、灰度降本或紧急故障转移。

#### 代价是什么
若目标模型与源模型在参数支持（如特定的温度上限、思考预算、系统提示词格式）上存在不一致，可能导致客户端特定的请求参数在上游执行时被忽略或报错。

## 计费倍率折算 (Credit Weights)

管理员可为每个模型独立配置三个维度的计费权重（基于百万 Token）：
- **输入权重 (Input Weight)**；
- **输出权重 (Output Weight)**；
- **思考推理权重 (Reasoning Weight)**。

每次请求结算时，系统将消耗的实际 Token 乘以对应权重，折算为统一的虚拟点数（Credits）并从用户配额中扣除。

## 运维约束与排查路径

### 失效场景
1. **上游不支持模型探测接口**：部分第三方中转或定制推理引擎未实现 `GET /v1/models` 端点，点击「自动探测」会返回 404，此时必须手动填写 Model ID；
2. **推理风格配置不匹配**：若模型为思考模型（如 DeepSeek-R1），但后台推理风格配置为非思考格式，前端可能无法将思考过程折叠进独立框，而是将 `<think>` 标签直接输出在正文中。

### 不明显的约束与前提
1. **服务商删除级联影响**：服务商与模型存在强依赖外键关联，删除一个服务商将导致挂载在其下的全部模型被级联删除或置为无效；
2. **透明路由不转换异构参数**：透明模型重定向仅替换向上游发送的 Model 字符串，若源客户端传入了目标模型不支持的高级参数（如特定的采样范围或思考预算），请求可能在上游报错；
3. **密钥变更不可逆性**：保存服务商时使用 `OBSIDIAN_SECRET_KEY` 派生子密钥加密 API Key。若运行期间更换了主密钥，此前已加密的 API Key 将无法解密，调用将返回解密失败。

### 排查路径
1. **上游调用 401 报错**：在管理后台重新编辑该服务商，确认重新填入的 API Key 是否有效，点击「测试连接」核对连通性；
2. **路由重定向未生效**：核对模型配置中的“目标模型”字段是否指向了正确的下级模型。
