# 服务商与模型

服务商保存连接方式，模型保存使用方式。先配置服务商，再添加它提供的模型，可以让多个模型共用同一套地址和凭据。

## 配置服务商

打开 `/admin/providers`，填写名称、类型、Base URL 和 API Key。

| 类型 | 上游接口 |
| --- | --- |
| `openai` | OpenAI 兼容接口 |
| `anthropic` | Anthropic Messages 接口 |

Base URL 使用上游提供的基础地址，不要填成完整的聊天请求路径。需要额外 HTTP 请求头时，在服务商配置中添加。

保存后测试连接。模型发现只能用于提供了相应模型列表接口的上游；发现失败并不一定表示聊天不可用，可手动配置模型后测试。

## 密钥保存

服务商 API Key 由实例密钥派生的密钥加密后写入数据库，管理接口不会回传其明文。修改服务商时，按表单提示保留或替换已有凭据。

`OBSIDIAN_SECRET_KEY` 或自动生成的 `secret.key` 必须长期保存。更换主密钥不能自动重新加密已有凭据，丢失后需要重新录入上游密钥。

## 配置模型

打开 `/admin/models`，选择服务商并填写模型字段：

| 字段 | 用途 |
| --- | --- |
| 内部 ID | 程序生成的记录标识 |
| 上游模型 ID | 实际发送给上游的名称 |
| 展示名称 | 网页显示的名称 |
| `api_name` | 可选的外部 API 名称 |
| 能力与推理选项 | 决定可选的输入、生成和推理参数 |
| 计费设置 | 计算实例内部用量点数 |

模型能力需与上游一致。勾选视觉、工具或生图能力，不会改变上游本身的支持范围。

## 模型路由

可以让一个对外模型转交另一个模型执行。客户端继续使用对外名称，服务端按配置选择实际执行模型。

路由只支持受约束的单跳关系。变更前检查目标模型的启用状态、权限关系和能力，不能假定不同模型的上下文、工具调用或推理参数完全一致。

给用户提供稳定的 API 名称时，使用说明应明确这个名称代表的服务范围。

## 用量点数

模型可以设置输入、输出、推理相关权重，以及按请求计费的点数。上游报告的用量经适配后用于结算。

图像生成按生图路径的计费规则结算，不能直接套用文本 Token 数。点数是实例内的管理单位，不等同于上游实际货币账单。

## 排查模型不可用

先测试服务商连接，再检查模型 ID、启用状态、能力和路由目标。普通用户看不到模型时，还需核对用户组授权。

删除服务商会影响其关联模型。操作前确认影响范围，并在需要时先迁移模型到其他服务商。
