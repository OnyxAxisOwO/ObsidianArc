# 全局系统设置

本文档说明 Obsidian Arc 管理后台「系统设置」模块中各个配置分区的字段含义、生效机制、导入导出规则与运维排查路径。

---

## 动态配置与生效机制

### 做了什么
所有业务配置项保存在数据库 `settings` 表中，后端在服务启动时读取并加载至内存结构体；在后台修改配置提交时，后端更新数据库行并同步刷新内存缓存。配置变更在运行中即时生效，无需重启进程。

### 为什么这么做
允许管理员在不中断现有长连接请求或重启服务进程的前提下，动态调整站点公告、试用限制、附件大小上限与清理策略。

### 代价是什么
多实例部署时，某个实例修改配置若未借助数据库变更通知或轮询同步，其他实例可能在短时间内存在配置读取延迟（依赖各实例的定期同步机制）；必须对所有输入字段进行严格的类型校验，防止非法值存入破坏内存结构体。

## 配置分区与字段说明

### 1. 站点标识与关于页 (Identity & About)

| 配置键 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `site.name` | *(空，默认为 Obsidian Arc)* | 站点对外展示的品牌名称。修改后同步更新网页 Title 与导航栏。 |
| `site.description` | *(空)* | 站点副标题或登录表单提示文本。 |
| `about.title` | *(空)* | 个人中心「关于」弹窗的标题。 |
| `about.body` | *(空)* | 「关于」弹窗正文，支持 Markdown 语法。 |
| `home.notice` | *(空)* | 悬挂在主对话区顶部的横幅通知正文，支持 Markdown 语法。 |
| `home.notice_dismissible` | `true` | 是否允许用户手动点击右上角关闭横幅通知。设为 `false` 则强制常驻。 |

### 2. 首页门面与访客试用 (Landing & Trial)

| 配置键 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `landing.mode` | `login` | 首页展示形态：`login`（登录表单）、`intro`（介绍页）、`chat`（对话界面）。 |
| `landing.intro` | *(空)* | 门面为 `intro` 时的自定义 HTML 代码，由 `safe-intro` 白名单过滤后渲染。 |
| `landing.trial_enabled` | `false` | 门面为 `chat` 时，是否允许免登录访客直接发起对话试用。 |
| `landing.trial_turns` | `3` | 允许免登录访客试用的最大轮数上限。 |
| `landing.trial_model` | *(空)* | 访客试用绑定的模型 ID。留空时自动选取首个启用的可用模型。 |

### 3. 全局对话参数 (Chat Defaults)

| 配置键 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `chat.default_system_prompt` | *(空)* | 实例级默认系统提示词。模型未单独设置且对话未指定时生效。 |
| `chat.max_turns` | `40` | 单会话重发历史回溯轮数截断上限。超过此轮数时仅向模型重发最近指定轮数的有效消息。 |

### 4. 额度规则 (Limits)

| 配置键 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `quota.admins_bypass` | `false` | 超级管理员是否绕过配额限制。开启后管理员调用不计入配额拦截（但仍会记录审计账本）。 |
| `quota.usage_display` | `absolute` | 前端额度展示风格：`absolute`（具体数值）、`remaining`（剩余百分比）、`used`（已用百分比）。 |

### 5. 附件与文件限制 (Attachments)

| 配置键 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `attachments.max_mb` | `6` | 允许单次上传的单文件大小上限（MB），系统硬上限 64MB。 |
| `attachments.retain` | `false` | 是否持久保留附件物理文件。为 `true` 时，即便触发自动修剪，已关联消息的物理文件也不会被删除。 |

### 6. 定期自动修剪 (Cleanup)

| 配置键 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `attachments.purge_after_days` | `0` (不清理) | 附件最大保存天数。超过此天数的附件物理文件将被清理。 |
| `attachments.purge_daily_at` | *(空)* | 每日自动执行清理的时刻（24 小时制，如 `03:30`）。 |
| `attachments.orphan_minutes` | `60` | 孤儿附件清理阈值。上传后未关联到任何消息的物理文件在此时间（分钟）后被删除。 |

### 7. 开发者 API 总开关 (API Access)

| 配置键 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `api.enabled` | `false` | 全站 `/v1` 开发者接口与 API Key 创建总开关。关闭时普通用户无法创建 Key，外部 `/v1` 调用直接返回 403（管理员不受限）。 |

## 配置导出与导入

- **导出配置**：点击「导出设置」将当前表单的所有有效配置字段序列化为 JSON 文件并下载；
- **导入配置**：点击「导入设置」上传备份的 JSON 文件。系统校验字段合法性后执行批量更新，遇到未知字段自动跳过并记录提示，表单自动刷新为最新导入值。

## 运维约束与排查路径

### 失效场景
1. **`chat.max_turns` 设置过小导致上下文丢失**：若将其设为 1 或 2，多轮问答将几乎失去历史记忆，模型无法理解前序提问的代词与指代；
2. **`attachments.purge_after_days` 误配置过小**：若配置为较小数值（如 1 天），历史对话中昨天上传的截图或文档会被物理删除，导致用户查看旧对话时附件无法加载；
3. **`attachments.purge_daily_at` 时间格式错误**：必须为 `HH:MM` 格式，若格式非法，定时清理调度器将无法解析定时时刻。

### 不明显的约束与前提
1. **热配置更新不中断长连接**：配置变更立即刷新内存指针，但对于修改发生前已经建立的流式推流连接，继续使用发起时的配置上下文，不会中途强制截断；
2. **导出文件不含加密凭证**：系统设置导出的 JSON 仅包含全局文本配置（如站点名、门面模式、额度规则），不包含上游服务商的 API Key 凭证，无法用于服务商凭据恢复；
3. **数据库并发锁保障**：多节点并发修改配置时，数据库使用 `INSERT ... ON CONFLICT (key) DO UPDATE` 施加行锁，保证配置单条更新的原子性。

### 排查步骤
1. **配置未生效排查**：在管理后台刷新页面核对表单回显值，检查标准输出日志中是否有配置反序列化报错；
2. **附件手动清理测试**：点击右上角「立即清理附件」，查看后端返回的已删除文件数与释放空间，确认清理逻辑是否正常执行。
