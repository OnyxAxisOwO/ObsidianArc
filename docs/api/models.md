# 模型发现接口

`GET /v1/models` 与 `GET /v1/models/{id}` 端点遵循 OpenAI Models API 规范，供客户端查询当前可用模型列表及其元数据。

---

## 接口规范

- **请求方法**：`GET`
- **请求地址**：`https://<你的域名>/v1/models`
- **认证方式**：HTTP Header `Authorization: Bearer sk-oa-<你的APIKey>`

---

## 权限隔离与过滤机制

### 做了什么
服务端在处理该请求时，首先根据 API Key 关联的账户及其所属用户组，解析该账户被授权访问的模型集合；同时若该 API Key 在创建时显式绑定了特定模型子集，则进一步取交集。返回的 `data` 数组仅包含当前调用方实际具备调用权限的模型。

### 为什么这么做
防止外部调用方枚举系统中存在的其他未授权模型（如其他业务部门的私有模型或未对外部开放的高单价模型），符合最小特权安全原则。

### 代价是什么
每次拉取模型列表均需进行一次用户组与 Key 权限的关联查询计算；客户端无法通过此接口查看全站所有存在的模型总量。

## 调用示例

### 1. cURL 查询

```bash
curl https://ai.example.com/v1/models \
  -H "Authorization: Bearer sk-oa-xxxxxxxxxxxx"
```

```json
{
```

## 运维约束与排查路径

### 失效场景
1. **返回的模型列表为空**：
   - 该 API Key 所属用户组未被勾选任何模型白名单（且未开启全模型自动授权）；
   - 或者创建 Key 时绑定的特定模型在后台被管理员删除或禁用。
2. **第三方客户端拉取模型失败**：
   - 部分第三方客户端要求必须实现 `GET /v1/models/{id}` 单模型查询端点；若请求的 ID 不在授权白名单内，接口返回 404。

### 不明显的约束与前提
1. **权限交集过滤机制**：最终返回的模型列表取 API Key 绑定子集与所属用户组授权白名单的交集，任一处未授权均不会返回；
2. **熔断与禁用模型自动脱敏**：被断路器标记为 `AutoDisabled` 或管理员手动禁用的模型会在此接口中自动过滤，外部无法探测到其存在；
3. **模型别名优先**：若模型配置了 `api_name`，列表中的 `id` 展示该别名，客户端调用时需使用该别名发起请求。

### 排查步骤
1. **核验权限矩阵**：在管理后台「用户管理」中找到 Key 的持有者，核对其所属用户组在「用户组管理」中的模型勾选清单；
2. **确认启用状态**：在「模型管理」中核对目标模型是否处于启用状态（Enabled）。
