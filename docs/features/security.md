# 安全防护与风控策略

本文档说明 Obsidian Arc 的人机验证、基于模型的注册审核、频控防护机制、密码学哈希与附件安全规则。

---

## Cloudflare Turnstile 人机验证

### 做了什么
系统原生接入 Cloudflare Turnstile 无感验证码方案，支持在后台独立开启以下三处门禁验证：
- 注册门禁：`turnstile.on_signup`
- 登录保护：`turnstile.on_login`
- API Key 创建保护：`turnstile.on_api_key`

服务端在校验前端提交的 Token 时，通过持久化 HTTP 连接池与 Cloudflare API 进行通信。

### 为什么这么做
相比传统的图形扭曲字母验证码或滑动拼图，Turnstile 减少了正常用户的交互步骤，同时提高了对脚本自动识别破解的拦截门槛。

### 代价是什么
1. **外部网络依赖**：服务端验证阶段必须能连通 Cloudflare 的验证端点（`https://challenges.cloudflare.com/turnstile/v0/siteverify`），若宿主机无法访问外网或存在网络阻断，验证会超时失败；
2. **前端资源加载**：需要在浏览器端加载 Cloudflare 提供的外部 JavaScript 脚本，在网络受限环境可能导致页面加载变慢。

## 注册行为智能审查 (`screening` 模块)

### 做了什么
在注册流程中，系统可将申请人的非隐私注册特征（用户名、邮箱域名与命名特征、QQ 号码、客户端 User-Agent 以及该 IP 历史注册账户数）发送给指定的大语言模型，由模型判断该注册行为是否属于自动化批量注册。

审查支持配置三档敏感度模式：
- **宽松模式 (`loose`)**：仅拦截特征明显的机器垃圾账号；
- **标准模式 (`normal`)**：默认模式，拦截随机生成的字符序列，放行具备常规语义的昵称与人名；
- **严格模式 (`strict`)**：对疑似批量生成的账号进行拦截，适用于遭受自动化攻击的阶段。

### 为什么这么做
传统的验证码无法防范真人众包或绕过验证码后的自动化程序注册垃圾账号，而静态规则与正则表达式维护成本高且容易误伤。利用大语言模型对多维注册元数据进行上下文模式分析，能够在不增加用户填写额外复杂表单负担的前提下识别自动化注册特征。

### 代价是什么
1. **注册延迟增加**：每次注册需额外等待一次上游模型调用的网络往返（通常增加 500ms~2s 延迟）；
2. **产生额外调用成本**：消耗审查模型的 Token 配额与调用费用；
3. **存在概率性误判**：模型推理存在误拦截真实用户（False Positive）的可能性。

### 故障放行机制 (Fail-Open)

#### 做了什么
若执行审查的模型发生超时、网络不可达或上游报错，系统记录告警日志并默认放行该次注册。

#### 为什么这么做
防止因上游第三方模型服务商的网络抖动或欠费停机，导致系统自身的注册功能被完全阻断。

#### 代价是什么
在上游模型服务不可用期间，批量自动化注册脚本可能趁机绕过智能审查成功创建账号，需要管理员事后结合审计日志进行清理。

## 频控与防暴力破解

系统从多个维度对写入接口进行速率限制：
- **全站注册频控**：限制每分钟最大注册数（`registration.per_minute`）与每小时最大注册数（`registration.per_hour`）；
- **单 IP 注册限制**：限制单 IP 在时间窗口内（`registration.per_ip_window_minutes`）允许注册的账户数量（`registration.per_ip`）；
- **兑换码防暴力枚举**：按 IP 与账号双重维度对输错兑换码的行为施加指数退避与临时封禁。

## 密码安全 (Argon2id)

### 做了什么
密码哈希存储统一采用 Argon2id 算法，并在内存中通过信号量机制限制并发计算数量（默认最多 4 个并发）。

### 为什么这么做
Argon2id 具备内存硬度特性，能有效抵御基于 GPU 与专用硬件（ASIC）的离线暴力破解；通过并发控制，防止攻击者利用大量并发哈希计算耗尽宿主机 CPU 与内存资源。

### 代价是什么
计算单次哈希需要消耗约 19 MiB 内存和数十毫秒 CPU 时间。在高频并发登录时，超出信号量容量的请求需排队等待，增加了瞬时并发下的认证延迟。

## 准入策略与身份收集

- **邮箱验证**：开启 SMTP 服务后，可强制要求注册成功后必须点击邮件中的激活链接才允许发起对话；
- **域名过滤 (`registration.email_domains`)**：支持配置邮箱后缀白名单（仅允许特定企业域名）或黑名单（屏蔽临时垃圾邮箱域名）；
- **QQ 号码收集 (`registration.qq_requirement`)**：可选 `off`（关闭）、`optional`（选填）或 `required`（必填）。

## 附件存储生命周期与清理

### 做了什么
1. **单文件尺寸限制**：管理后台可配置单文件最大大小（`attachments.max_mb`，系统硬上限 64MB）；
2. **孤儿附件自动物理删除 (`attachments.orphan_minutes`)**：若用户在输入框上传了文件但最终未发送消息或关闭了页面，定时巡检协程会在达到设定时长（默认 60 分钟）后从磁盘中删除该物理文件；
3. **过期附件修剪**：支持配置附件最大保留天数（`attachments.purge_after_days`）与每日定时清理时刻（`attachments.purge_daily_at`）。

### 为什么这么做
防止因用户反复上传大文件而不发送消息导致服务器磁盘被垃圾文件耗尽。

### 代价是什么
定时巡检任务在扫描大批量文件时会产生短时间的磁盘 I/O 消耗；若误将保留天数设得过短，会导致历史消息中引用的旧图片被物理删除。

## 运维约束与排查路径

### 失效场景
1. **反向代理未传递真实 IP 导致单 IP 频控失效**：若未开启 `OBSIDIAN_TRUST_PROXY`，所有外部请求均以代理服务器回环 IP 统计，会导致全站正常用户因共享同一个 IP 配额而快速触发频控；
2. **Turnstile 秘钥配置错误**：若填写的 Site Key 与 Secret Key 不匹配，前端或后端校验会一直返回 `invalid-input-secret`，导致所有注册或登录被拦截；
3. **审查模型超时配置过短**：若审查模型选用响应较慢的大模型且超时时间过短，审查会频繁触发故障放行。

### 不明显的约束与前提
1. **Argon2id 内存占用与并发限制**：单次哈希运算固定占用约 19 MiB 内存，最大并发由 `OBSIDIAN_ARGON_MAX_PARALLEL` 控制（默认最多 4），高并发实例下不可盲目调大该并发数，否则极易触发宿主机 OOM；
2. **Turnstile 校验依赖外网连通**：服务端验证 Turnstile 必须能连通 Cloudflare 官方 API，若宿主机处于断开外网的隔离网络中，验证将直接失败；
3. **附件清理以实际关联为准**：未关联任何对话消息的孤儿文件会在达到配置时间（默认 60 分钟）后被后台协程物理删除，临时上传但未点击发送的文件无法长期驻留。

### 排查路径
1. **注册被拦截原因核实**：在管理后台「请求日志」或命令行标准输出中搜索 `registration rejected`，查看具体是被频控拦截、Turnstile 校验未通过还是被 AI 审查模型判定拦截；
2. **沙盒测试审查规则**：进入管理后台「安全风控」->「沙盒模拟审查」，手动输入测试特征，查看模型生成的判定理由。
