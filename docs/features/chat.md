# 对话与附件

登录后，首页就是对话工作区。左侧管理历史会话，中间阅读回答；设置、用量和 API 密钥等面板会在工作区旁边打开。

## 发起对话

选择一个可用模型，输入问题后发送。回答会逐步显示。模型支持推理且管理员配置了相应选项时，可以选择推理等级，并单独查看思考内容。

不同模型支持的参数不同。界面中的能力标记来自管理员配置，不能让上游模型获得原本不支持的能力。

## 管理历史会话

可以新建、搜索、重命名和置顶会话。删除入口取决于用户组权限。

回答生成时可以切换到其他会话，原请求会继续在当前网页中接收。切回来后显示已经收到的内容。这个行为只在当前标签页有效；刷新或关闭页面会断开连接。

编辑历史提问会从该位置重新生成后续内容。重新生成回答也会改变后续上下文，操作前留意界面提示。

## 停止回答

点击停止后，浏览器取消请求，服务端随之取消上游调用，并尝试保存已收到的部分回答和结算用量。

已经生成的内容仍可能产生费用。实际收费取决于上游的用量报告和计费规则，不能把停止按钮理解为撤销整次消费。

## 添加附件

输入区支持图片和文本附件。图片会在浏览器中进行必要的缩放和压缩；文本文件的内容会作为上下文提交。能否理解图片取决于所选模型是否支持视觉输入。

单文件上传大小默认上限为 6 MB，管理员可以调整，最高 64 MB。图片数据默认不长期保留：发送后清理；管理员开启 `attachments.retain` 后，才会保留供历史上下文使用。

保留策略变化不会恢复已经删除的图片。需要长期保存重要结果时，请自行下载或备份。

## 阅读与保存回答

回答支持 Markdown、表格、代码块和数学公式。代码块可以复制，也可以保存为文件。数学公式使用浏览器的 MathML 展示，支持范围以当前渲染器为准。

模型输出中的 HTML 不会作为可执行页面插入。普通 Markdown 外部图片会转换为链接，应用管理的附件和生图结果使用单独的图片组件展示。

## 上下文与用量

`chat.max_turns` 默认是 40，用于限制重发给模型的历史范围。它不会替代模型自身的上下文长度限制：单条很长的消息也可能超出上游容量。

回答下方的耗时和 Token 统计是否显示，由用户组权限控制。个人总用量可在 `/usage` 查看，见[用量与额度](./quota-and-billing)。
