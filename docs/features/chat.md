# 对话与流式交互

本文档说明 Obsidian Arc 对话交互界面的数据流转、会话切换机制、请求中断处理与渲染安全设计。

---

## 布局与交互结构

对话界面采用以下布局结构：
- **历史会话栏**：宽度为 260px，通过负外边距（Negative Margin）实现折叠与展开，折叠时仅调整外层容器位移；
- **阅读列**：对话正文约束在 680px 宽度内；
- **统计信息栏 (Stats Line)**：每次回答生成后，底部记录并展示本次请求的总耗时、首字延迟（TTFT）、输入/输出/推理 Token 数量以及平均生成速率（Tokens/sec）。

---

## 流式传输与思维链解析

### 1. SSE 流式传输
前端通过 Fetch API 发起 HTTP 请求并读取 ReadableStream，服务端使用 Server-Sent Events (SSE) 协议分块推送文本增量。输出末端通过 CSS 动画显示光标标记。

### 2. 思维链解析与折叠
针对返回推理思考过程的模型（如 DeepSeek-R1、Claude 思考模式、OpenAI 推理模型）：
- **推理深度选择**：支持配置思考预算等级（关闭、低、中、高）；
- **独立容器折叠**：思考内容在独立的 `<details>` 容器中展开并随流式内容滚动，生成完毕后自动收起，与最终回答正文分离展示。

---

## 会话切换与后台接续

### 做了什么
在流式响应生成过程中，用户切换至其他会话时，当前请求的 Fetch 连接并不关闭，数据流由全局状态控制器继续接收并缓存在内存队列中。用户重新切回原会话时，界面将从本地状态中重放已接收的全部内容并恢复展示。

### 为什么这么做
长文本生成与深度推理通常需要耗时 30 秒至数分钟。允许用户在等待期间查阅其他历史会话或进行其他操作，避免界面被长时间独占锁定。

### 代价是什么
多会话并发流式生成会同时占用客户端内存与浏览器的网络连接数；若用户并发发起了多个流式请求并在后台持续运行，每个请求都会占用服务端的并发限制配额与数据库连接。

---

## 请求中断与持久化机制

### 做了什么
用户点击「停止」按钮或直接关闭浏览器页面时，前端主动关闭 HTTP 连接，触发服务端的请求上下文取消（`r.Context().Done()`），服务端随之中断向上游模型的网络 Socket；同时，服务端使用 `context.WithoutCancel` 启动结算流程，将已接收的有效片段写入数据库并按实际消耗的 Token 扣减配额。

```text
用户中断 / 客户端断开连接
       │
       ▼
关闭前端 HTTP 连接 ──► 取消 r.Context() ──► 中断向上游 Provider 的连接
                                            │
                                            ▼
                                  上游停止生成并停止计费
                                            │
                                            ▼
                       context.WithoutCancel 写入已生成文本与实际消耗记账
```

### 为什么这么做
及时断开上游网络连接可以终止上游计费，避免继续生成冗余内容；同时中途产生的实际 Token 开销和部分回答依然具有业务价值，必须持久化并扣费，不能随请求上下文取消而被丢弃。

### 代价是什么
若上游提供商的中转实现不支持断开连接即停止计费（例如在上游端忽略了客户端 RST 信号并完整生成），服务端仍然会被上游扣除全量费用；同时，脱钩后的保存逻辑脱离了原请求超时控制，若数据库异常可能导致清理协程挂起。

---

## 历史分支编辑与重试

- **编辑历史消息**：修改历史提问并提交后，系统将从该消息节点截断后续上下文并创建新的对话分支，重新向上游请求生成；
- **重新生成**：针对不满意的回答，点击重试按钮将触发对上一轮提问的再次请求，覆盖原有回答。

---

## 附件与图片预处理

### 客户端图片本地降采样

#### 做了什么
用户上传图片作为多模态对话输入时，前端使用 HTML5 Canvas API 在浏览器端对大尺寸图片进行等比例缩放与 JPEG 压缩，将尺寸限制在模型适用的分辨率范围内后再上传。

#### 为什么这么做
直接上传数兆的原图会占用较多服务器带宽和存储空间，且大多数视觉大模型在输入前同样会将图像缩放至特定分辨率区间。前端预压缩可显著降低网络传输与服务端附件存储负担。

#### 代价是什么
客户端压缩消耗终端设备的 CPU 与内存，在性能较低的移动端设备上可能产生数百毫秒的图像处理耗时；压缩可能抹除细微的图像边缘细节。

### 文本附件合并
支持向输入框拖入 `.txt`、`.py`、`.js`、`.json`、`.md` 等纯文本代码文件，文件内容以折叠上下文形式附加在消息体中发送。

## 内容渲染与安全规范

### 1. 基于 AST 的受控渲染
Markdown 文本经词法解析为 Token 语法树后，通过 `document.createElement()` 与 `textContent` 创建并插入 DOM 节点。全站 Vue 模板杜绝使用 `v-html`，防止不可信模型输出构造跨站脚本注入。

### 2. 协议白名单
超链接仅放行 `http://`、`https://` 与 `mailto:` 协议，过滤 `javascript:` 等脚本伪协议；图片标记不加载外部不受信的 `<img>`，转换为安全超链接展示。

### 3. 数学公式渲染
采用浏览器原生 MathML 标准进行公式排版，支持行内 `$ ... $` 与独立块级 `$$ ... $$` 公式，无需引入外部大型排版库。

### 4. 代码块语法识别与保存
- **语言识别**：针对未标注语言类型的代码块，通过关键字特征进行推断；
- **一键保存为文件**：根据识别出的语言自动匹配扩展名（如 `.go`、`.py`、`.sql`），用户点击可直接下载为本地代码文件。

## 上下文截断控制

### 做了什么
系统在全局配置中提供 `chat.max_turns`（默认 40 轮）参数。当多轮对话的历史消息数超过该阈值时，向模型发送上下文时仅保留最近指定轮数的有效消息。

### 为什么这么做
防止长会话历史不断累积导致超出模型的上下文窗口限制（Context Window），同时控制长对话每次重发完整历史所消耗的高昂 Token 费用。

### 代价是什么
模型无法访问被截断早期的历史指令与对话背景，可能在长会话后程遗忘最初制定的角色设定或业务规则。

## 运维约束与排查路径

### 失效场景
1. **反向代理开启缓冲导致流式卡顿**：Nginx 未设置 `proxy_buffering off` 时，流式内容会停留在 Nginx 内存缓冲区中，直至数据填满才一次性推给前端；
2. **上下文过大触发上游报错**：若单轮消息内容过长（如贴入数十万字代码），即便轮数未超限，同样会触发上游服务商的 `context_length_exceeded` 错误；
3. **模型不支持视觉输入**：向仅支持纯文本的模型上传图片时，上游会返回 `400 Bad Request`，提示模型不具备多模态能力。

### 不明显的约束与前提
1. **后台接续仅限单标签页**：会话切换后台推流由当前网页内的单例网络请求控制器维持，若用户直接刷新或关闭浏览器标签页，网络 Socket 将立即断开并触发请求取消；
2. **持久化与取消脱钩**：客户端中断连接后，服务端取消向模型服务商的 Socket，但已生成文本的保存与 Token 扣减结算使用 `context.WithoutCancel` 异步执行，确保账本数据不遗漏；
3. **Markdown 渲染防 XSS 机制**：前端 Markdown 渲染采用词法 Token 树并用 `document.createElement()` 创建纯文本节点，不使用 `v-html` 或 `innerHTML`，不支持在 Markdown 中嵌入可执行脚本或自定义表单。

### 排查路径
1. **流式推流异常断开**：登录管理后台「请求日志」，根据该次请求的唯一 ID 查看 HTTP 状态码与上游详细错误返回；
2. **前端渲染解析错误**：打开浏览器开发者工具 Console 面板，查看是否有未匹配的 Markdown Token 或 DOM 操作异常。
