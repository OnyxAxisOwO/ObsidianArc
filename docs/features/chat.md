# 对话与附件

登录后，首页就是对话工作区。左侧管理历史会话与项目，中间阅读回答；设置、归档、用量和 API 密钥等面板会在工作区旁边打开。

## 发起对话

选择一个可用模型，输入问题后发送。回答会逐步显示。模型支持推理且管理员配置了相应选项时，可以选择推理等级，并单独查看思考内容。

不同模型支持的参数不同。界面中的能力标记来自管理员配置，不能让上游模型获得原本不支持的能力。

## 项目与多会话（Projects）

项目为会话提供立项上下文（Prompt 继承）。每个账号最多可创建 64 个项目，每个项目拥有独立的名称（≤80 字符）与系统指令（≤8000 字符）。

- **系统指令继承**：项目内发起的所有会话会自动将项目的指令提示词作为系统提示词的前置上下文，适用于编码规范、角色扮演、翻译约定或长期任务。
- **手风琴折叠栏**：侧边栏提供“对话”与“项目”选项卡。在项目列表可展开或收起手风琴，清晰浏览每个项目归属的对话列表。
- **项目内多会话**：在同一个项目下可以开启多条独立的对话分支，各自保持不同的上下文和对话进展。
- **项目生命周期**：支持创建项目、修改项目名称与提示词、删除项目。删除项目后，其中的对话不会丢失，会自动脱离项目并作为普通无项目会话保留。
- **终端与 API 支持**：控制台提供完整的 `project list`、`project show`、`project create`、`project edit`、`project delete` 命令，且 `chat list --project <id>` 支持按项目筛选。

## 管理历史会话

侧边栏列出历史会话，支持新建、搜索、重命名与置顶：

- **操作菜单**：会话右侧提供“更多”（三点图标）菜单，包含**重命名**、**归档**与**删除**操作。删除入口取决于用户组是否允许删除会话。
- **会话归档**：
  - 当管理员在系统设置中启用 `chat.allow_archive`（默认开启）时，用户可将不再活跃但需要长期留存的会话一键归档。
  - 归档后的会话会从主侧边栏列表中移出，保持主列表清爽。
  - 用户可在侧边栏底部点击“已归档对话”打开 `/archive` 侧面板，检索已归档的会话，支持一键“取消归档”恢复到活跃列表，或永久删除。
  - 控制台与 API 完整支持归档管理：`chat archive <id>`、`chat unarchive <id>`、`chat list --archived`。
- **并行与切换**：回答生成时可以切换到其他会话，原请求会继续在当前网页中接收。切回来后显示已经收到的内容。这个行为只在当前标签页有效；刷新或关闭页面会断开连接。
- **消息编辑与重试**：编辑历史提问会从该位置重新生成后续内容。重新生成回答也会改变后续上下文，操作前留意界面提示。

## 停止回答

点击停止后，浏览器取消请求，服务端随之取消上游调用，并尝试保存已收到的部分回答和结算用量。

已经生成的内容仍可能产生费用。实际收费取决于上游的用量报告和计费规则，不能把停止按钮理解为撤销整次消费。

## 添加附件

输入区支持图片和文本附件。图片会在浏览器中进行必要的缩放和压缩；文本文件的内容会作为上下文提交。能否理解图片取决于所选模型是否支持视觉输入。

单文件上传大小默认上限为 6 MB，管理员可以调整，最高 64 MB。图片数据默认不长期保留：发送后清理；管理员开启 `attachments.retain` 后，才会保留供历史上下文使用。

保留策略变化不会恢复已经删除的图片。需要长期保存重要结果时，请自行下载或备份。

## 阅读与保存回答

回答支持 Markdown、表格、代码块和数学公式。代码块可以复制，也可以保存为文件。数学公式使用浏览器的 MathML 展示，支持范围以当前渲染器为准。

模型输出中的 HTML 不会作为可执行页面插入。普通 Markdown 外部图片会转换为链接，应用管理的附件和生图结果使用单独的图片组件展示。

## Canvas

管理员在「系统设置 → 对话」开启 `chat.canvas_enabled` 后，模型可以把一个完整的网页（HTML、`<style>` 中的 CSS 和 `<script>` 中的 JavaScript）写进 `canvas` 代码块。回答里的 `canvas` 和 `html` 代码块头部会出现「在 Canvas 中运行」按钮，点击后页面在对话旁的侧栏里运行，可以拖宽或全屏，「重新运行」会从头加载一次。

页面运行在沙箱框架中：无法访问本站、你的账号、Cookie 和本地存储，也不能联网加载脚本、字体或图片，不能弹窗或提交表单。代码只在你的浏览器中运行，不会发送到服务器，也不会写进地址栏。关闭开关后，按钮和已打开的侧栏都会消失。

## 上下文与用量

`chat.max_turns` 默认是 40，用于限制重发给模型的历史范围。它不会替代模型自身的上下文长度限制：单条很长的消息也可能超出上游容量。

回答下方的耗时和 Token 统计是否显示，由用户组权限控制。个人总用量可在 `/usage` 查看，见[用量与额度](./quota-and-billing)。
