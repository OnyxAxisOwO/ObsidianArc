# 账号与权限

每个账号拥有自己的对话、API 密钥、偏好设置和用量记录。管理员通过用户组分配模型与功能权限。

## 个人设置

在 `/settings` 中修改账号资料、外观和对话偏好。账号偏好会保存到服务端，重新登录时加载；本地临时状态和正在生成的请求不会因此在设备间接续。

需要迁移自己的历史记录时，可以导出个人数据。导出范围与限制见[备份与迁移](../admin/backups-and-data)。

## 用户组决定什么

| 权限 | 对使用者的影响 |
| --- | --- |
| 模型访问 | 决定模型列表中可选择的模型 |
| API 访问 | 决定是否可以创建密钥和调用兼容 API |
| 统计显示 | 决定回答下方是否显示耗时与生成速率 |
| 删除会话 | 决定是否可以删除自己的历史对话 |
| 额度策略 | 决定请求频率和各周期的用量上限 |

新账号加入管理员指定的注册默认组。初始创建的 `Default` 组允许访问全部模型，管理员可以按需要调整。

API 权限还受全站 `api.enabled` 控制。全站开关关闭后，管理员也不能使用 `/v1`。

## 管理员与普通用户

管理员可以打开后台，并绕过部分用户组限制。额度是否对管理员生效由 `quota.admins_bypass` 控制，默认允许绕过额度限制；调用仍会记录用量。

实例会阻止移除最后一名有效管理员。交接管理权限时，先确认另一名管理员可以正常登录。

## 对话的访问范围

普通用户只能访问自己的对话。实例管理员拥有后台审阅权限，可以查看用户历史对话；自托管实例的数据访问规则应由运营者向使用者说明。

## 权限变化后

切换分组或修改权限后，新请求按当前授权判断。原先已经开始的生成不会因为权限变更自动成为一条全新的请求。

缺少模型或无法创建密钥时，应先让管理员核对账号所属组，再检查全站开关与模型启用状态。
