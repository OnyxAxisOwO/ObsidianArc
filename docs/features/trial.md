# 访客试用与落地页模式

本文档说明 Obsidian Arc 的首页展示形态、访客免登录试用机制、资源防护边界与排查路径。

---

## 首页展示形态

管理员可在管理后台「系统设置」中切换主页门面模式（`landing.mode`）：

| 门面模式 | 标识 | 界面行为 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **登录注册门面** (默认) | `login` | 直接展示登录/注册表单卡片，未登录访客无法进入对话界面。 | 内部私密团队中枢或严格封闭的站点。 |
| **产品介绍引导页** | `intro` | 展示管理员配置的富文本介绍页面，底部提供“登录/注册”入口。 | 面向外部公众的产品展示页面。 |
| **直接对话工作台** | `chat` | 首页直接呈现对话面板。若开启试用开关，访客可直接在此发起对话。 | 开放体验站点或演示站点。 |

---

## 自定义介绍页沙箱 (`safe-intro`)

### 做了什么
当门面模式配置为 `intro` 时，管理员可在后台配置自定义 HTML 富文本内容（`landing.intro`）。前端在渲染前通过 `web/src/lib/safe-intro.ts` 将 HTML 字符串载入内存中脱离 DOM 树的 `<template>` 节点，遍历节点并按白名单重建：
- 仅放行展示标签：`p`、`h1`-`h6`、`ul`、`ol`、`li`、`code`、`pre`、`blockquote`、`strong`、`em`、`a`；
- 移除所有 `style` 内联样式与所有 `on*` 事件监听属性；
- 超链接仅保留 `http://`、`https://` 与 `mailto:` 协议，过滤 `javascript:` 等伪协议。

### 为什么这么做
允许管理员在不重新编译前端代码的情况下自定义主页文案与布局，同时防止恶意脚本注入导致的管理员会话窃取或钓鱼攻击。

### 代价是什么
管理员无法在介绍页中使用内联 CSS 样式、自定义字体颜色、第三方统计脚本（如 Google Analytics、Baidu 统计）或嵌入 iframe 视频播放器。

## 访客免登录试用机制

当首页模式为 `chat` 且开启 `landing.trial_enabled=true` 时，未登录访客可直接发起模型对话。

```text
未登录访客发起提问
       │
       ▼
[频控与容量检查]
1. 单 IP 速率限制 (20 次/小时)
2. 全站实例预算限制 (240 次/小时)
3. 最大并发连接数 (最多 6 个并发)
       │
       ▼ (校验通过)
调用指定试用模型流式生成 (限制最多 600 输出 Token)
       │
       ▼
达到最大试用轮数 ──► 返回提示引导注册正式账号
```

## 无状态试用架构

### 做了什么
访客发起的对话不在服务端数据库创建会话记录（`conversations`）、消息记录（`messages`）或持久化附件，服务端不维护访客的上下文状态。客户端在每次请求时将历史轮次完整提交给服务端，服务端按接收到的消息数组长度判定当前轮数是否超出限制。

### 为什么这么做
1. **降低存储开销**：大量匿名访客的单次偶发提问若持久化落盘，会向数据库写入大量无效垃圾记录；
2. **隐私安全**：避免在未授权状态下持久化未知访客的数据；
3. **架构简化**：无需为匿名访客生成临时账户或跟踪 Session 生命周期。

### 代价是什么
1. **客户端网络开销增加**：多轮对话时，客户端每次请求需重复回传此前所有的对话历史，增加了上行带宽占用；
2. **轮数校验依赖客户端上报**：客户端若伪造或截断回传的消息数组，可能绕过基于消息数量的轮数计算（但仍受单 IP 与全站总频控限制）。

## 流量控制与资源保护

为了防止未登录接口被脚本批量消耗 API 额度，试用系统内建以下硬性限制：

### 1. 文本长度与 Token 限制
- **单条消息最大字符数**：`MaxMessageChars = 4000`；
- **总上下文最大字符数**：`MaxTotalChars = 24000`；
- **最大输出 Token 限制**：`MaxTrialOutputTokens = 600`（强制截断长文本生成，降低单次开销）。

### 2. 轮数限制 (`landing.trial_turns`)
管理员可配置访客允许试用的最大轮数（默认 3 轮）。超过该轮数后，接口返回达到上限提示，前端展示登录注册引导。

### 3. 多层频控与并发隔离
- **单 IP 频控 (`burstPerAddress`)**：单个客户端 IP 在 1 小时窗口内最多允许执行 20 次提问；
- **全站实例总频控 (`burstPerInstance`)**：全实例 1 小时内向所有访客发放的总试用次数上限为 240 次；
- **并发连接数隔离 (`maxConcurrent = 6`)**：试用请求最多同时占用 6 个并发上游连接，超出并发直接排队或报错，避免未登录流量挤占注册用户的连接池。

## 试用模型指定 (`landing.trial_model`)

管理员可在后台指定试用专属绑定的模型 ID（例如配置为低成本模型）：
- 若未显式配置，系统默认选取首个启用的可用模型；
- 该配置仅对未登录试用生效，注册用户登录后按其所属用户组的授权列表选用模型。

---

## 运维约束与排查路径

### 失效场景
1. **全站试用预算打满**：若短时间内访问量激增达到 240 次/小时，正常访客会收到“试用额度已耗尽”报错，直至时间窗口滚动恢复；
2. **IP 伪造导致单 IP 限制失效**：若反代未配置好 IP 穿透，所有访客会被识别为同一个内网 IP，20 次提问后全站所有访客均会被单 IP 限制拦截；
3. **试用绑定的模型失效**：若配置的 `landing.trial_model` 在服务商端被删除或欠费，访客试用将直接报错，不会自动降级为其他可用模型。

### 不明显的约束与前提
1. **无状态设计与数据不落盘**：匿名试用对话在服务端不创建任何会话、消息或附件记录，完全依赖客户端每次提交历史上下文，刷新网页即丢失会话；
2. **三层容量硬隔离**：除单 IP 限制（20 次/小时）与全站限额（240 次/小时）外，系统硬性限制最多 6 个并发连接（`maxConcurrent = 6`），超出立即排队或返回错误；
3. **Token 截断与模型指定**：试用请求强制限制最大输出 Token 为 600，且绑定的试用模型必须属于系统已启用的模型列表。

### 排查路径
1. **访客无法使用**：在管理后台「系统设置」检查 `landing.mode` 是否为 `chat`，且 `landing.trial_enabled` 是否已勾选开启；
2. **频控触发排查**：查看标准日志，若出现 `rate limit exceeded for guest trial`，表明触发了单 IP 或全站小时频控；
3. **测试连通性**：使用无痕浏览器窗口访问首页，打开 Network 面板检查 `/api/chat/trial` 接口的返回状态码与错误信息。
