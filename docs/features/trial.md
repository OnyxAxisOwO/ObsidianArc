# 访客试用

管理员可以决定未登录用户打开首页时看到什么，也可以开放有限轮数的对话试用。

## 首页模式

| `landing.mode` | 展示方式 |
| --- | --- |
| `login` | 登录页，默认模式 |
| `intro` | 管理员填写的介绍页 |
| `chat` | 访客对话页面，可另行开启试用 |

介绍页内容来自 `landing.intro`，只支持经过允许列表处理的展示 HTML。脚本、事件属性和任意内联样式不会直接执行。

## 开启试用

在系统设置中选择 `chat` 模式，开启 `landing.trial_enabled`，设置试用模型和轮数。

默认允许 3 轮，最多可配置 20 轮。未指定试用模型时，程序从可用模型中选择；指定模型后，应确认它仍然启用且能正常响应。

试用调用使用实例的上游凭据，会消耗服务商额度。切回登录页或关闭试用开关后，试用接口不再提供生成。

## 试用记录与限制

试用内容只保留在当前网页中，不会创建正式账号、历史会话或消息记录。刷新页面后不能像已登录用户那样从历史列表恢复。

后续请求携带服务端签名的续接凭据，用于验证已用轮数。同时还有独立的频率和并发限制：

| 项目 | 当前上限 |
| --- | --- |
| 单条消息 | 4,000 字符 |
| 总上下文 | 24,000 字符 |
| 输出 | 600 Token |
| 单 IP | 每小时 20 次 |
| 单进程试用总量 | 每小时 240 次 |
| 同时生成 | 6 个试用请求 |

试用频率与并发预算保存在进程内，多个实例不会自动共享这份预算。服务繁忙时返回限制提示，不会无限排队等待。

## 验证配置

用未登录窗口打开首页，发送一条简短问题。请求路径为 `POST /api/trial/chat`。

无法试用时，依次检查首页模式、试用开关、模型状态和频率限制。通过反向代理部署的实例，还应确保客户端地址识别正确。
