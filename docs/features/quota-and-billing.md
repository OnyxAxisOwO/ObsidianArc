# 用量与额度

网页对话与 API 调用使用同一账号的额度。打开 `/usage` 可以查看当前用量、周期结束时间和可用的重置卡。

## 哪些限制会生效

额度策略按字段继承，优先级为：**用户设置 > 用户组设置 > 全局设置**。下级没有填写的字段继续沿用上级，显式关闭某个周期则不再执行该周期的限制。

当前支持：

| 限制 | 说明 |
| --- | --- |
| RPM | 每分钟请求次数 |
| TPM | 每分钟 Token 用量 |
| 5 小时 | 该周期的请求数、Token 或点数上限 |
| 每周 | 该周期的请求数、Token 或点数上限 |
| 每月 | 该周期的请求数、Token 或点数上限 |

当前没有独立的每日额度窗口。用户组设置为每名成员提供相同规则，不是全组共用一个余额。

## 周期何时重置

5 小时、每周和每月额度以账号注册时间为起点，按固定周期划分，不是每日零点或自然月第一天统一刷新。月周期会处理月份长度差异。

具体结束时间以用量面板显示为准。RPM 和 TPM 则按分钟时间桶计算。

## 为什么会预留用量

发起请求前，系统根据模型配置预留预计用量；生成结束后释放预留，并记录实际用量。这可以防止多个同时生成的请求各自消耗同一份剩余额度。

因此，正在生成的回答可能暂时占用额度。若提示不足，检查预留所需的模型上限，以及其他尚未完成的请求。

进程异常终止可能使预留来不及释放。当前清理任务会修剪旧计数桶，不能据此认为未结算预留会在十分钟后自动恢复。

## 点数与账本

点数由管理员配置的模型计费规则计算。它是实例内部的用量单位，不代表上游账单中的货币金额。

账本保留请求消耗。额度重置只改变限制用的计数，不删除历史账本，也不会撤销已经发生的上游费用。

`quota.usage_display` 控制页面展示具体数值、已用比例或剩余比例，不改变实际限额。

## 使用兑换码与重置卡

兑换码与重置卡分两步使用：

1. 在用量面板输入兑换码，领取一张重置卡。
2. 需要恢复额度时，再使用尚未过期的重置卡。

同一账号对同一个兑换码只能领取一次。兑换码的截止时间与领取后卡片的有效期分别计算。

管理员也可以直接给账号发卡。详情见[兑换码](../admin/codes)。
