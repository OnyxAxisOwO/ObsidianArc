## 目标

写一份详细的中文文档（VitePress 站点页面），覆盖退群闭环功能和全部接口，重点是机器人对接协议——你能拿着它直接开发 QQ 机器人。

## 改动清单

### 1. 新建 `docs/admin/departures.md`（主交付物）

标题「退群处理与邀请回收」，遵循站点惯例（单一 H1、`##` 分节、端点表格、```http 代码块、设置键表格、相对链接不带 .md）。章节：

1. **功能概述** — 闭环逻辑；封禁 vs 删除对比表（数据保留、QQ 号占用、可恢复性）；收卡规则（按账本、未结算算 0、已用卡如实记录、每邀请只收一次）
2. **后台操作** — AdminUsers 两个操作按钮、AdminInvites 退群记录、邀请人通知与徽标、SSH 控制台 `user depart` / `invite departures`
3. **配置** — 设置键表（`bot.webhook_token`、`bot.departure_mode`）、在安全页配置、令牌写后不可见
4. **管理接口** — `POST /api/admin/users/{id}/departure` 与 `GET /api/admin/departures` 的请求/响应/错误码完整表
5. **机器人接入协议**（最重的一节，开发机器人就看这里）：
   - 端点 + Bearer 鉴权（常量时间比较、空 token=端点关闭、错误不区分原因）
   - 请求体字段表（qq 必填 `^[1-9][0-9]{4,14}$`、mode 可选）
   - 四个状态词 `departed / already_departed / unknown / refused` + `result` 字段表
   - `cards_due` vs `cards_revoked` 语义
   - 错误表（401/400/429 + code）与限流（突发 10、持续约 5 秒 1 次、仅计有效 token 请求）
   - 幂等与重试建议（网络失败重试安全、429 退避、unknown/refused 不重试）
   - 每种状态一个完整 ```http 请求/响应示例
   - 机器人侧处理流程（事件 → 调用 → 按 status 分支 → 播报文案建议）
6. **安全模型与边界** — bot 不能处理管理员账号；非浏览器客户端不发送 Origin 头即可通过同源校验；管理员路径的 last-admin 与自操作守卫

### 2. 侧边栏注册

`docs/.vitepress/config.mts` 管理后台组、`邀请码` 条目后加 `{ text: '退群处理', link: '/admin/departures' }`。

### 3. 交叉链接

- `docs/admin/invites.md` 末尾加一句链接到新页（邀请闭环的延伸）
- `docs/admin/system-settings.md` 的设置键表补 `bot.webhook_token` / `bot.departure_mode` 两行

### 4. 验证

`npm --prefix docs run build` + `npm --prefix docs test`（站点测试强制单一 H1、zh-CN、所有内链可解析、无死链）。
